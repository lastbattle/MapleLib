# Byte and hexadecimal conversion performance

Date: 2026-09-07

Scope is limited to `Helpers/ByteUtils.cs`, `PacketLib/HexTool.cs`, and `PacketLib/HexEncoding.cs`. The behavior contract includes wildcard parsing, accepted whitespace and separators, optional `0x` prefixes, malformed-input exceptions, output letter case, trailing spaces, byte-to-ASCII control replacement, and null behavior already covered by tests.

## Measurement plan

The benchmark harness is `benchmarks/MapleCrypto.Benchmarks/ByteHexBenchmarks.cs`. It measures 16, 256, and 4,096-byte inputs and reports elapsed time plus allocations for:

- compact hexadecimal parsing;
- parsing with a prefix on every byte and colon separators;
- `ByteUtils.BytesToHex` uppercase output with a header and trailing spaces;
- both `HexTool` array formatters (uppercase and lowercase, each with trailing spaces);
- `HexEncoding.ToStringFromAscii`.
- the single-byte, packet-reader, and packet-writer `HexTool` overloads plus batched `HexEncoding.IsHexDigit` calls.

The benchmark project uses .NET 10, BenchmarkDotNet 0.15.6, one launch, three warmups, five measured iterations, and `MemoryDiagnoser`. Correctness coverage was extended before production edits in `ByteUtilsTests.cs` and `PacketLibAdversarialTests.cs`. The parser tests include a frozen baseline oracle over 2,000 seeded strings containing valid digits, malformed characters, prefixes, ASCII separators, and Unicode whitespace. Deterministic cases compare bytes or exact exception type/message/parameter; wildcard cases validate pair counting and accepted/rejected syntax because their byte values are intentionally random.

At 4,096 bytes, the direct implementation changed compact parsing from 57.947 µs/282,704 B to 15.403 µs/4,120 B (3.76x faster, 98.5% fewer allocated bytes); prefixed/separated parsing from 72.923 µs/307,280 B to 44.618 µs/4,120 B (1.63x faster, 98.7% fewer allocated bytes); `ByteUtils.BytesToHex` from 132.317 µs/156,736 B to 3.802 µs/24,616 B (34.8x faster, 84.3% fewer bytes); uppercase `HexTool` from 30.297 µs/319,920 B to 2.748 µs/24,600 B (11.0x faster, 92.3% fewer bytes); lowercase `HexTool` from 76.355 µs/147,552 B to 2.790 µs/24,600 B (27.4x faster, 83.3% fewer bytes); and ASCII mapping from 1.088 µs/16,432 B to 0.981 µs/8,216 B (1.11x faster, 50.0% fewer bytes).

The retained production implementation uses exact-size direct formatting, direct scalar decoding for extended notation, and runtime vectorized recognition/decoding for plain hexadecimal input. Compact 4,096-byte input improved again from the direct version's 15.403 µs to 1.693 µs with identical 4,120 B output allocation; this is 34.2x faster than the original 57.947 µs baseline.

With hardware intrinsics disabled, final compact parsing measured 5.403 µs at 4,096 bytes, still 10.7x faster than the original runtime baseline, while extended separated input measured 46.697 µs. The final overload run measured the single-byte formatter at 1.949 ns versus its frozen 3.612 ns implementation, and the packet-reader/writer overloads at 190–192 ns and 1,840 B versus 1,451–1,470 ns and 12,584 B. `HexEncoding.IsHexDigit` measured 1.085 ns with zero allocation, so it remains unchanged.
