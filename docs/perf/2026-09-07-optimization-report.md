# MapleLib exhaustive performance audit — 2026-09-07

## Scope and acceptance

Audit every source function in `MapleLib/MapleLib`, including constructors and accessors. A source inventory is coverage bookkeeping, not evidence that a function was optimized. Keep public behavior, binary formats, ownership/disposal, lazy loading, thread safety, and runtime/package targets unchanged. Retain measured improvements exceeding 3% and observed variability, or meaningful allocation reductions without a latency regression. Stop individual candidates after 3–5 measured plateau comparisons or a documented compatibility/maintenance risk. Trivial and already optimized functions may remain unchanged with an explicit reason.

The user explicitly requested parallel agents, overriding the optimizer skill's single-agent default. Agents review and prepare independently; the root grants one exclusive lease at a time for builds/tests/benchmarks. No competing agent CPU workloads during measurement. Ambient machine load and timing variance must still be recorded; exclusivity within this task does not guarantee an idle host.

## Measurement ledger

Current topic ledgers:

- [LRU cache measurements](2026-09-07-lru.md): retain timestamp removal and direct write lock on TryGet; single hit approximately 51–52 ns to 22–23 ns (about 56% lower latency, 0 B). Reject global monitor lock because read-only contention regressed approximately 2x. Three independent confirmation sets recorded. Manager cache-key work is measured separately below; its baseline already contains this LRU change.
- [Serialization review and live-corpus harness](2026-09-07-serialization.md): retain vectorized escape detection and direct escaping. Controlled live-corpus Classic XML mean 2.974 to 2.194 ms (26.2% lower), Combined XML 3.082 to 1.944 ms (36.9% lower); allocations fall about 67.3%. Unchanged JSON control differs by 0.9%. Initial noisy 5x result is excluded. Exact output hashes match; 7 focused tests pass with and without intrinsics, and full Release suite passes 366/366. Pixel encoders also retained: exact-order scalar palette/alpha unrolling plus SSE4.1 palette distances reduce 1024-square DXT3 from 14.589 to 8.060 ms (44.8%) and DXT5 from 18.623 to 10.472 ms (43.8%). Runtime dispatch retains an optimized scalar fallback; live hashes and 2,048 color/2,048 alpha oracle blocks match with intrinsics enabled and disabled. Final pixel-state Release suite passes 376/376.
- [Byte/hex measurements](2026-09-07-byte-hex.md): retain exact-size formatters, direct extended-notation parsing, and runtime vectorized plain-hex recognition/decoding. Compact 4 KiB parsing approximately 57.95 to 1.69–1.74 microseconds (33–34x faster), with 98.5% lower allocation. - [IMG manager cache keys](2026-09-07-img-manager-cache-key.md): cached loads 47.77 to 33.09–34.27 ns (28–31% lower), 136 to 56 B, against a baseline already containing the LRU change. Three confirmations; culture-equivalence tests pass.

## Orchestrator review notes

- `Configuration/ApplicationSettings.cs`, `UserSettings.cs`: field-only settings containers; no handwritten functions to optimize.
- `Configuration/ConfigurationManager.cs`: all declared functions/accessors inspected. Accessors/default resets are trivial. Load/Save and temp-file replacement deliberately synchronize and flush to disk; removing durability or validation to improve timings would violate compatibility. Custom key conversion benefits indirectly from ByteUtils work. Leave remaining functions unchanged absent an I/O workload demonstrating a worthwhile compatible change.
- `Configuration/EncryptionKey.cs`: all functions/accessors inspected. Cached WzKey generation is already guarded by a lock; retain invalidation/validation and notification ordering. Hex conversion delegates to ByteUtils. No independent change proposed.
- `Helpers/FileReplacement.cs`: both functions inspected. Backup existence probing and copy-before-replace preserve recovery behavior; no shortcut justified.
- `Helpers/ErrorLogger.cs`: all functions/accessors inspected. Queue accessors and constructor are trivial. SaveToFile repeatedly removes saved references from the head of a List, potentially quadratic for large logs. Candidate requires tests for concurrent clear/log/save and reference identity before measuring a batched removal. GetErrorSnapshot deliberately copies; do not expose the mutable queue.
- `Helpers/ByteUtils.cs`, `PacketLib/HexTool.cs`, `PacketLib/HexEncoding.cs`: all functions inspected; formatting and parsing allocate temporary objects per byte. Assigned to the byte/hex workstream. Rotation/endian wrappers are already runtime primitives; private HexToByte helpers need no independent benchmark if eliminated from the measured callers.
- `PacketLib/PacketReader.cs`, `PacketWriter.cs`: all declared functions/accessors inspected. Most are BinaryReader/BinaryWriter delegates, stream position setters, or compatibility overloads. String reads/writes allocate encoded byte arrays; bounded stack/pool buffers are a candidate, with arbitrary Encoding, short reads, exception ordering, and stream ownership to preserve. Hex writer methods inherit the byte/hex candidate. Keep primitive wrappers unchanged.
- `ClientLib/CCrc32.cs`: all three functions inspected; public 4/8-byte overloads delegate to a table loop. The >=16-byte unrolled branch is unreachable under its guard. Removing dead source is not a speedup; pointer-dependent xorInitialCrc behavior prevents careless scalar/API replacement. `CWvsPhysicalSpace2D.GetConstantCRC` chains fixed CRC inputs; possible algebraic optimization would need a dedicated compatibility oracle. `MapleStoryLocalisation.cs` is enum-only.
- `Helpers/StringUtility.CapitalizeFirstCharacter`: multiple temporary allocations when lowercase; candidate for string.Create with culture-sensitive char.ToUpper preserved. Empty/uppercase returns and null behavior must remain identical.
- `Helpers/ImageFormatDetector.cs`: all functions/accessors inspected. AnalyzeImageData builds a HashSet<byte> with at most 256 members; fixed presence storage is a candidate. RGB cardinality and exact returned statistical tuple must remain unchanged. Format selection, dimension validation, and DXT eligibility are small branch/validation wrappers. Do not change format choices for a speed claim.
- `Converters/ImageConverter.cs`: all seven functions inspected. ToImage is a cast; GetImageFormat is a switch; BitmapToBytes is one required owned copy. Texture PNG/JPEG and WPF/WinForms conversions delegate to codecs and enforce stream lifetimes. A direct pixel bridge requires indexed, premultiplied, DPI, and color/profile compatibility tests; defer a risky behavior-changing shortcut.
- `MemoryLimits.EnsureFileSize`: validation plus one filesystem size read; retain its guard and error semantics. `WzDataReader.cs`: all seven conversion methods inspected; primitive type branches and runtime parsing, with existing span-based percent-suffix handling. No independent speedup proposed.
- `PacketLib/AbstractPacket.ToArray`: MemoryStream fast path already exists; generic-stream path requires copying and restoring Position. Pre-sizing a scratch stream is only a candidate if non-MemoryStream packets are measured.
- `PacketLib/Acceptor.cs`, `Connector.cs`, `Monitor.cs`: all functions/accessors inspected. Network and event coordination dominate; preserve callbacks, buffer ownership, partial-receive handling and raw-socket requirements. No live external connection or packet interception needed for this audit. Buffer pooling would need lifetime/API redesign because subscribers may retain readers.
- `PacketLib/Session.cs`: all functions/accessors inspected. Primitive state and validation are trivial; send/receive perform required protocol checks. Header parsing creates unnecessary reader/copy objects; send encrypts into one clone then copies into a second buffer. These are candidates for loopback/differential tests and span-based crypto, not justification to remove caller isolation or send locking.
- `PacketLib/MapleHandshakePolicy.cs`, `MapleRoleSessionProxyFactory.cs`: all functions/accessors inspected. Version checks, shared-proxy synchronization, IV clone, and four factory delegates preserve contracts. Authority text is infrequent diagnostic work; no optimization proposed.
- `PacketLib/MapleRoleSessionProxy.cs`: all functions, nested BridgePair constructors/accessors, and callbacks inspected. Most coordinate lifecycle, cancellation, publication, and event dispatch. TrySendToServer and HandleServerPacket clone before Session.SendPacket clones again; candidate for measured removal with session output tests. Do not change publication locks or event snapshots for a timing shortcut. TryDecodeOpcode is already a runtime primitive.
- `PacketLib/MapleSessionPacketEventArgs.cs`, `SocketInfo.cs`: constructors assign state and create required owned buffers; getters are automatic. Remaining PacketLib enum files contain no functions.
- `WzLib/WzStructure/InfoTool.cs`, `MapleBool.cs`, `Foothold.cs`: all functions/accessors/operators inspected. Primitive wrappers, nullable conversions, and required fresh mutable property objects; sharing fallback vectors would break mutation isolation. No independent candidate.
- `WzLib/WzStructure/Data/PortalType.cs`: all three lookup methods and dictionary construction lambdas inspected. Existing ordinal-ignore-case reverse dictionary avoids repeated scans. Forward dictionaries could become switches/arrays only with invalid-enum behavior retained and measured gain; low priority.
- `WzLib/WzStructure/Data/MapStructure/MapDirectionInfo.cs`: all functions/accessors/lambdas inspected. Deep clones preserve unknown data ownership and numeric ordering is required. NextQueueName restarts at zero and can become quadratic for newly generated queues; monotonic allocation cursor is a candidate only if event queues are large enough. Preserve original names, collisions, and unknown fields.
- `WzLib/WzStructure/Data/CharacterStructure/CharacterClassTypeInfo.cs`: all constructor/getters/two lookup functions inspected. JobTypes is a public mutable array, so caching a lookup would silently go stale. Small linear scan retained. AutoLieDetector and TimeMob constructors only assign fields.
- Remaining `WzLib/WzStructure/Data` source functions reviewed except `MobStructure/MobData.cs`: BackgroundType is two constant-string switches; FieldLimitType is four bit checks plus a repeated Enum.GetValues maximum (candidate for immutable cached metadata); FieldType formats enum descriptions with temporary strings (cold UI candidate); MapConstants and ItemIdsCategory are constant-divisor checks. CharacterClassType enumerates/copies enum values per GetMatchingJobs call (candidate for private immutable iteration data). CharacterSubJobFlagType, QuestAreaCodeType, and QuestMedalType integer ToEnum methods use boxing Enum.IsDefined(Type, object), a candidate for generic Enum.IsDefined preserving undefined-value fallbacks; their string converters and QuestStateType use runtime parsing with existing normalization. InventoryType.GetByType allocates enum values and a capturing predicate (candidate for direct defined-value check; unknown values currently return nullable NONE, not null). PetSkillFlag uses tiny bit operations. CharacterJob and CharacterJobPreBBType formatted-name methods allocate per character; candidate for one string construction preserving spaces/special cases/digits. Pre-BB encode/decode preserves distinct sorted job ordering; HasFlag already receives runtime optimization. MobAttackData, MobBanishData, MobSelfDestructionData and MobSkillData are automatic mutable accessors only.
